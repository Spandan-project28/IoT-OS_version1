# Executive Summary

IoTOS AI is an AI-powered, local-first desktop application that transforms how beginners build Arduino and ESP32 projects.

Instead of forcing users to learn multiple disconnected tools, IoTOS AI provides a single intelligent workspace where users can describe a project in natural language, generate firmware with AI, upload it to supported hardware, and immediately observe results.

Prototype V0.1 validates one seamless workflow:

> **Describe → Generate → Upload → Run**

Every workflow now begins with a project — created from a reusable template, generated by AI, or created manually — and every project is then saved, reopened, edited, and uploaded through the same consistent workflow, regardless of how it began.

# Phase 9 — Project-Centric Product Direction

IoTOS AI is evolving from a template-first application into a project-centric application, while preserving the beginner-first experience described throughout this document. The fastest path for a beginner — choose a template, land in the Editor — remains exactly as fast and exactly unchanged.

## Core Idea

Projects are the primary editable unit inside IoTOS AI. A template is simply one way of creating a project.

## Core Concepts

- **Project** — the working, editable unit a user actually builds inside the Editor. Every project, regardless of how it was created, is saved, autosaved, uploaded, and edited through the same workflow described under Current Product Capabilities.
- **Template** — a reusable project definition. Selecting a template creates a new, independent, editable project initialized from that definition. The template itself is never opened or edited.
- **Project Origin** — provenance metadata assigned automatically at the moment a project is created: `template`, `ai`, or `manual`. It is immutable and never user-editable — a user cannot set, choose, or change a project's origin at any point; it may only be shown as an informational label, such as an origin badge. Origin records only how a project came to exist. It never determines what a project can do, how it behaves, or what it is permitted to do — every project behaves identically after creation, regardless of origin.

## New Projects Page Workflow

The existing template gallery on the Projects page is unchanged: users can still browse built-in templates and select one to open directly in the Editor, exactly as before.

A new "+" action is added to the Projects page. It opens a small menu with exactly two options:

- **Create New Project**
- **Open Existing Project**

### Create New Project

Lets a user start a new project without a template. The user:

1. Enters a project name.
2. Selects a target board.
3. Chooses a storage location (the default workspace location is offered).

The Editor then opens immediately with the new project active. From that point on, the project behaves identically to a project created from a template — the only differences are its starting content, which is empty, and its recorded origin, `manual`.

### Open Existing Project

An additional entry point into the existing project-opening workflow already used by Recent Projects — not a new persistence system. It lets a user browse for and open any existing IoTOS project file, alongside reopening a project already listed under Recent Projects.
